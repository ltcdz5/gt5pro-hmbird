## 二、**但它还不能用** ✗（重要，务必先读）

**写入 `echo 1 > /proc/hmbird_sched/scx_enable` 会整机硬挂死** ✗（adb 失联、USB 不枚举 ⇒ 强制重启；`ro.boot.bootreason=reboot`）。

- 挂死点：`hmbird_ctrl(true)` → `bpf_hmbird_reg()` → `hmbird_ops_enable()`
- 含义：**启用之后 fork 的运行期语义不成立** ✗ —— 不是接口不对，而是**这套实现还不完整**
- 需要补的（已知清单）：`slim_walt_*` 在内核侧与厂商模块**各持一份**（语义必须统一）、任务属性跟踪（`sched_prop` / `key_task`）启用前的初始化、`hmbird_sched_class` 与 `ext_sched_class` 并存时 BPF struct_ops 注册是否互斥

> 之前曾记录"写 `scx_enable=1` 不挂死"——那是因为当时那个写处理是**空壳**（只写值、未真正启用）✓，**不能**解读为"启用是安全的" ✗。

## 三、安全边界（照做）

1. **不要**写 `scx_enable=1`（会硬挂死）✗
2. 任何对外镜像请把 `CONFIG_HMBIRD_SCHED_CORE` **保持 n**（默认就是 n ✓）
3. 刷机前备好回退镜像与"断路器"内核（无 `/sys/kernel/sched_ext` 的那版）
4. 恢复经验：硬挂死后长按电源强制重启即可，系统会自动回到未启用状态（`scx_enable` 是内核变量，重启复位）✓

## 四、结论

**"接口齐 + 家族被链接进内核" ≠ 能用** ✓。
本项目目前的价值是：把**接口层与 ABI 安全边界**做扎实了（这一层社区此前没有人公开做过 6.1 / SM8650 ✓），并**明确指出了剩下的真正缺口**（fork 运行期语义）✗。
