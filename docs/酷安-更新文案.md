真我 GT5 Pro 上 hmbird（风驰）的一点尝试

本文由 DeepSeek 协助整理。

做了什么

用 DeepSeek 帮忙，在一台真我 GT5 Pro（RMX3888 / SM8650 / ColorOS 16）上自编 6.1.141 内核，把 hmbird / sched_ext 的内核侧接口按出厂内核逐条对齐，并把厂商模块的装载条件摸清了。到现在，**风驰已经能在游戏里真正跑起来** 🎮

为什么做

6.1 / SM8650 这条线上，没找到现成的、成熟的、开放源代码的 hmbird 移植方案。

社区里能翻到的，要么是更新的平台（6.6 / SM8750 往上），要么停在「能编过但跑不起来」，要么干脆缺源码。没有可抄的作业，就只好对着出厂内核一点点对 🔍

适用条件（很重要，先看这段）

这套东西不是通用的，前提是：

1. 内核基线必须是 OPPO 系（OKI），也就是出厂那种 6.1.141-android14-11-o-…，不是纯 GKI 或别的厂商基线；
2. 设备树里 hmbird 类型为 HMBIRD_OGKI（SM8650 就是这一档；HMBIRD_GKI / HMBIRD_EXT 属别的平台，不能混用）；
3. 厂商模块 oplus_bsp_sched_ext.ko 及其依赖（oplus_bsp_game_opt.ko、oplus_bsp_sched_assist）在位，且按依赖顺序加载。

不满足上面任何一条，都不适用，硬套只会白忙或出问题 ⚠️

思路与借鉴

思路：不另写调度器，而是以出厂内核为准，把它暴露给厂商模块的那一层（符号、CRC、结构体布局、proc 条目）在自己树上「对回来」；再拿设备上的 493 个厂商模块当判据 —— 能装、不报错、不漂移，才算过。

过程中参考了社区若干公开工作（ferstar 的 GT5 Pro 源码镜像与 scx 分支、reigadegr 的 6.1 sched_ext 补丁与 hmbird_controller、WildKernels 的 A15 hmbird 补丁、wanwei1028 的 DT 版本兼容思路、murongruyan 的风驰 DTBO 模块等），在此一并致谢 🙏

目前的进度（如实说）

✅ 内核侧接口出来了：/proc/hmbird_sched 21 条，与出厂内核那半套一致（含 scx_enable）；
✅ 厂商模块装载后变 27 条，[scx_gov][scx_cpufreq_init] 也真的初始化了 4 个 cluster；
✅ 写 scx_enable=1 现在不会挂死（之前那次整机硬挂死没有复现）；
✅ **风驰真的生效了**：进游戏自动切到 scx 调度，退出游戏自动回到系统默认（uag）—— 第五人格、绝区零都实测通过，重负载下也没崩 🎯
🎁 还顺手做了个配套小模块 **fengchi-boot**（就 3 个文件）：开机把厂商那套模块按依赖顺序加载好，游戏时自动切换；顺便把内存优化（MGLRU）也一起做了。原来要装两个小模块，现在一个就够。

⚠️ 但这个模块**必须搭配我的自编内核使用**，单独刷没有任何效果。

怎么确认有没有生效：进游戏后用 **Scene** 看一眼 CPU 调速器，显示 scx 就是生效了（退出游戏会变回系统默认，这是正常的）。

谨慎说明

- 不建议普通用户尝试，也不建议主动 register 任何 scx 调度器。真出问题，请准备好回退镜像 🛟
- **千万不要用任何工具去「固定」风驰调度** —— 我实测过，会让手机直接死机 💀
- 如果你之前装过「官方调度屏蔽」类模块（比如 IMS_VAROS），要先卸掉，否则风驰没法工作；
- 可能与 Scene 的调度设置冲突（我没做完整对比测试），建议先把 Scene 的调度/调速器关掉再试。

水平有限，有错欢迎指正，我会协助机主更正。
