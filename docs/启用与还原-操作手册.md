# 启用与还原操作手册（内核态 hmbird + 厂商 scx）

> 适用镜像：`opt161b` / `opt162`（已在真机验证 hmbird 与 `scx` 共存并完整还原）。
> 本文的每一步都有**判据**；判据不通过就按该步的 ABORT 处理，不要继续往下走。
> 内核行号基于 HEAD `7cc87ec0d8dc`（分支 `opt162`），换镜像后**先重新 grep 再引用**。

## 零、前置条件

1. `scx` governor 必须存在。它由厂商模块 `oplus_bsp_sched_ext.ko` 提供；设备上**唯一** `insmod` 它的是守护模块 `fengchi-boot` 的 `service.sh`（见 `_audit/成功-t194游戏态启用与退出完整还原.md:14-18`）⇒ **停用守护模块 = 同时移除 `scx` governor**。停用时需手动按依赖序装载：

```sh
insmod /vendor/lib/modules/oplus_bsp_game_opt.ko
insmod /vendor/lib/modules/oplus_bsp_sched_ext.ko
```

2. 先做**只读盘点**（不改任何状态）：

```sh
POL=/sys/devices/system/cpu/cpufreq
cat $POL/policy7/scaling_available_governors     # 必须含 scx
ls -d $POL/policy*                              # 本机 = policy0 policy2 policy5 policy7（4 个）
for d in $POL/policy*; do echo "$d $(cat $d/scaling_governor)"; done
cat /proc/hmbird_sched/slim_stats
cat /proc/hmbird_sched/scx_enable                # ★这是「意图值」，不是状态（见 §四 口径一）
dmesg | grep -c 't42:'                           # 记录基线，后面只比增量
cat /proc/sys/kernel/random/boot_id              # 记录基线
MARK="MANUAL_$(date +%s)_$$"; echo "$MARK" > /dev/kmsg   # ★日志切片标记★
newd() { dmesg 2>/dev/null | sed -n "/$MARK,\$p"; }      # 只打印标记之后的内核日志
```

> ★为什么不用 `dmesg | wc -l` + `tail -n +N` 切片★：内核环形缓冲会覆盖旧行，`dmesg | wc -l` 可能**变小**，此时 `tail -n +$((N+1))` 直接吐空 ⇒ 误判「未见 enabled=1」而中止（t194 缺陷 B 就是这个）。改用 `/dev/kmsg` 标记 + `sed` 取标记之后的全部行（`newd`），与 t194 判据脚本同口径。

3. 确认无残留：`ps -A | grep -E 'fengchi|opgs|scrc'` 应为空；`scx_enable` 为 0；governor 全 `uag`。

## 一、进游戏/需要时启用：五步顺序闸门

### 为什么必须按这个顺序

`hmbird.c:5043` 是 `hmbird_gov_switch_away()` 的**唯一**调用点（启用前兜底），它**只在当前 governor 匹配 `scx` 时动作**，动作是把 governor 抢回 `uag` 并拒绝本次启用（返回 `-EBUSY`）。所以启用前必须先让 governor 是 `uag`，启用成功后再切 `scx`。

### step 1：全 policy 写 `uag`，并硬断言

```sh
POL=/sys/devices/system/cpu/cpufreq
for d in $POL/policy*; do echo uag > $d/scaling_governor; done
u=0; for d in $POL/policy*; do [ "$(cat $d/scaling_governor)" = uag ] && u=$((u+1)); done
[ "$u" -eq 4 ] || { echo "ABORT step1: gov_uag_n=$u (want 4)"; exit 1; }
echo "step1 gov_uag_n=$u"
```

> 断言值 `4` 是本机的 policy 目录数；换成别的机器请先数 `ls -d $POL/policy*`。**不要只靠注释说明顺序，要能中止流程。**

### step 2：打开真数据统计 `slim_stats`

```sh
echo 1 > /proc/hmbird_sched/slim_stats
[ "$(cat /proc/hmbird_sched/slim_stats)" = 1 ] || { echo 'ABORT step2'; exit 1; }
```

`slim_stats=0` 时统计记录函数会直接返回（`hmbird.c:345`、`:371-377` 的门控）⇒ 后面看到的「增量 0」是假象。

### step 3：开启 hmbird，并**用 dmesg 回读真实状态**

```sh
echo 1 > /proc/hmbird_sched/scx_enable
sleep 1
newd | grep -q 'enabled=1' || { echo 'ABORT step3: 未见 enabled=1'; exit 1; }
newd | grep 'scx_enable=1'
```

期望看到（`hmbird_sched_proc_main.c:299` 的打印）：

```
schedtune: hmbird_sched: scx_enable=1 -> hmbird_ctrl() rc=0, enabled=1
```

★不要用 `cat /proc/hmbird_sched/scx_enable` 判状态★：那个值是**用户意图**，写失败也不会回滚（`hmbird_sched_proc_main.c:285` 先发布、`:306-307` 失败直接 `return -EFAULT`）。

### step 4：断言本轮**没有**触发 t42 强切

```sh
t42=$(newd | grep -c 't42:');
[ "$t42" -eq 0 ] || { echo "ABORT step4: t42=$t42（governor 被强切过）"; exit 1; }
```

### step 5：全 policy 切 `scx`

```sh
for d in $POL/policy*; do echo scx > $d/scaling_governor; done
s=0; for d in $POL/policy*; do [ "$(cat $d/scaling_governor)" = scx ] && s=$((s+1)); done
[ "$s" -eq 4 ] || { echo "ABORT step5: gov_scx_n=$s"; exit 1; }
echo "ENABLED gov_scx_n=$s scx_enable=$(cat /proc/hmbird_sched/scx_enable)"
```

### 保持期

每 10~20 s 采一次：`scx_enable`、governor、`load`、`procs_running`、温度。出现 `failed to run for` / `hmbird disabled finished` / `WARNING:` 立刻停止并收集现场。

## 二、退出：四步完整还原

### 为什么内核不会帮你还原

正确顺序（先 `uag` → 开 hmbird → 再 `scx`）下，启用时 governor 已是 `uag` ⇒ `hmbird_gov_switch_away()` 整块跳过、`hmbird_orig_gov[]` **从未被写**；退出时 `hmbird_gov_restore()`（定义在 `hmbird.c:3717`）因「原值为空」的判据**整段跳过** ⇒ 内核**零写** governor。⇒ 必须由用户态显式写回。

### step 1：显式写 `uag`

```sh
for d in $POL/policy*; do echo uag > $d/scaling_governor; done
```

### step 2：关闭 hmbird，并回读 `enabled=0`

```sh
echo 0 > /proc/hmbird_sched/scx_enable
sleep 1
newd | grep -q 'enabled=0' || { echo 'ABORT exit-step2'; exit 1; }
newd | grep -E 'enabled=0|hmbird disabled finished'
```

期望看到：

```
<hmbird_sched>:hmbird disabled finished at jiffies = ..., clock = ..., reason =
schedtune: hmbird_sched: scx_enable=0 -> hmbird_ctrl() rc=0, enabled=0
```

### step 3：**再补写一次** `uag`（双保险）

```sh
for d in $POL/policy*; do echo uag > $d/scaling_governor; done
```

> ★不要在 `echo 0` 返回之前写 governor★ —— 关闭路径自身会做 governor 相关处理，抢在它前面写会污染结果。

### step 4：把统计开关恢复出厂默认

```sh
echo 0 > /proc/hmbird_sched/slim_stats
```

`slim_stats` 的出厂默认是 **0**（`hmbird_sched_proc_main.c:42` 变量 / `:415` 节点），启用时被我们置 1 ⇒ 退出必须归 0。

### 终态断言

```sh
u=0; s=0; for d in $POL/policy*; do g=$(cat $d/scaling_governor); [ "$g" = uag ] && u=$((u+1)); [ "$g" = scx ] && s=$((s+1)); done
echo "FINAL gov_uag_n=$u gov_scx_n=$s slim=$(cat /proc/hmbird_sched/slim_stats) intent=$(cat /proc/hmbird_sched/scx_enable) veto=$(cat /sys/module/kernel/parameters/hmbird_gov_veto)"
echo "FINAL t42=$(newd | grep -c 't42:') t55=$(newd | grep -c 't55:') warn=$(newd | grep -c 'WARNING:') stall=$(newd | grep -c 'failed to run for')"
echo "same=$([ "$(cat /proc/sys/kernel/random/boot_id)" = "$(cat /tmp/boot_id.orig)" ] && echo 1 || echo 0)"
```

期望：`gov_uag_n=4 gov_scx_n=0 slim=0 veto=N`、`t42=0 t55=0 warn=0 stall=0`、`same=1`。

## 三、残留判据：用**窗口增量**，不要用绝对值

`hmbird_stats` 里的 `gdsq_cnt` / `pcp_timeout_cnt` / `pcp_ldsq_cnt` / `pcp_enql_cnt` 等是**累计计数器**（`hmbird.c:307-311` 的结构体数组），随 uptime 单调增长。

`"退出后必须为 0"` 是**永远为假**的判据。正确做法：

1. 启用**前**采一次快照；
2. 退出**后**再采一次快照；
3. 只看**差值**；只有差值显著大于「同长度空转窗口」的基线时才判失败。

> 现状（诚实说）：`t194` 轮用的 `t194-residue.sh` 里窗口增量段有 regex 缺陷（`trailing backslash`）**没跑起来**，那轮的 M2 是用 **NODE start/end 快照逐项比对**替代的（`_audit/成功-t194游戏态启用与退出完整还原.md:89`）。⇒ 「窗口增量」这条口径本身**尚未在设备上跑通**。

## 四、判据口径三条（踩错就会得出相反结论）

### 口径一：`scx_enable` 是**意图**，不是状态

- 读回值 = 最后一次写入的意图（`hmbird_sched_proc_main.c:285` `WRITE_ONCE(*pval, val)`）；
- 写入失败**不回滚**（`:306-307`）；
- 真实状态只能从 dmesg 的 `enabled=`（`:299`）或 `hmbird_stats` 的环形 `sw_rec` 读；
- `docs/真机验证-opt60.md` 里「回读 0 ⇒ 未真正生效」的推论**已被证伪**，不要再用。

### 口径二：累计计数器只看增量

见 §三。

### 口径三：环形 `sw_rec` 的**最新一条**索引 = `(sw_idx + 4) % 5`

- `MAX_SWITCHS = 5`（`include/linux/sched/hmbird.h:219`）；
- `sw_update()` 先写 `sw_rec[*idx]` 再把 `*idx` 自增取模（`hmbird.h:360-364`：`*idx = ++(*idx) % MAX_SWITCHS`）⇒ 最新一条是 `(sw_idx + 4) % 5`；
- 实测样例（opt162 退出）：`sw_rec[1] = 4294956702 1 0 0` ⇒ `is_success=1`、`end_state=0`=`HMBIRD_DISABLED`；
- 四元组含义：`switch_at` / `is_success` / `end_state` / `switch_reason`。

## 五、★禁止项★

| 禁止 | 原因 | 依据 |
|---|---|---|
| 绝不写 `watchdog_enable` | stall 判据里**直接或上它**：`time_after(jiffies, last_runnable + hmbird_watchdog_timeout)) \|\| watchdog_enable` ⇒ 置 1 立刻判 stall 并自禁 | `hmbird.c:3486` |
| 绝不写 `heartbeat_enable` | 置 1 启动**应用保活检测**，`HEARTBEAT_TIMEOUT = 2500 ms` 内收不到保活就 `can't detect heartbeat, disable ext`（自禁） | `hmbird.c:4500`（超时常量）、`:4507`（门控）、`:4519-4521`（禁用路径）；默认 0 见 `hmbird_sched_proc_main.c:60` |
| 绝不置 `hmbird_gov_veto=1` | 开启后 governor 的 `scx` 写入会被内核否决（`EBUSY`），且关闭 hmbird 时恢复原值也会被自家否决拦下 | t188 实测：`B veto=Y ... refuse_delta=4`、4 条 `t93: refuse governor scx while hmbird is enabled (EBUSY)`（`_audit/成功-opt161b上机验证hmbird与scx稳定共存.md:78-96`） |
| 不要在 `echo 0 > scx_enable` 返回前写 governor | 关闭路径自身会处理 governor，抢写会污染结果 | 见 §二 step3 |
| 不要用工具「固定」`scx`（反复强写／锁死） | 历史教训：早期镜像上这条路会整机硬挂 | `docs/changelog.md` 2026-10-09 节第 5 条 |

## 六、失败处置

- **step3 未见 `enabled=1`**：立即 `cat /proc/hmbird_sched/scx_enable`（看意图）、`dmesg | tail -50`（看 `rc=` 与拒绝原因）。若 `rc=-EINVAL`，说明厂商模块未按依赖序加载（`ext_ctrl` 的模块闸门）；若是 `-EBUSY`，说明有其它持有者；
- **出现 `failed to run for` / `hmbird disabled finished`（非用户态触发）**：按 `docs/判据与陷阱.md` 的现场收集清单抓 `dmesg` + `/proc/last_boot_reason`，然后 `echo 0 > scx_enable` + 全 policy 写 `uag`；
- **出现 `pc :` / `WARNING:` / boot_id 变化**：停止实验，回退上一版镜像（见 `docs/固件与镜像.md`，若尚未创建则以发布说明为准）。
