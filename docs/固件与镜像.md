## 2. CRC 槽位表

三个符号的槽位地址随版本漂移，**取值恒定**：

| 版本 | sk_filter_trim_cap | iso_masks | task_is_scx |
|---|---|---|---|
| opt160 | 0x17e48e4 | 0x17eaea0 | 0x17edb5c |
| opt161 / opt161b | 0x17e4aa4 | 0x17eb060 | 0x17edd1c |
| opt162 | 0x17e4b64 | 0x17eb120 | 0x17edddc |

- 三槽**写入值恒为** `f5845708` / `cb6a4c44` / `b3071c68`（= 厂商期望值）。
- 原始自然值（未覆写时 vmlinux 里的值）：sk `0x43b2b8f0` / iso `0x9998675b` / tscx `0x61658a4e`。
- 为什么要覆写：厂商 .ko 在加载时校验这三个符号的 CRC，不匹配就拒绝加载（分析-厂商ko加载失败CRC.md:33-34）。

## 3. 四道 CRC 门禁（缺一不可）

| # | 脚本 | 调用方式 | 期望输出 |
|---|---|---|---|
| 1 | patch_crc_targeted_v2.py | `python3 patch_crc_targeted_v2.py Image.optN.crc <symvers> <vmlinux>` | OK sk_filter_trim_cap 0x43b2b8f0 -> 0xf5845708 @ 0x17e4b64 / OK find_task_by_vpid（同值，无需写）/ OK iso_masks 0x9998675b -> 0xcb6a4c44 @ 0x17eb120 / OK task_is_scx 0x61658a4e -> 0xb3071c68 @ 0x17edddc；`[CRC-PATCH-SUMMARY] written=3 skipped=0 total=4`；RC=0 |

## 5. 回退策略

### 5.1 硬回退（刷 boot）

- 回退件：`boot-v1.1-opt60-repacked.img`，md5 `5fd7909866e0de04b8e46cd9b388cc2e`（201,326,592 B）。
- ★该件不在 deploy 的 `$TBL` 表里★ ⇒ **不能**用 `-Ver` 回滚，只能由操作者直接 `fastboot flash boot` 刷入。
- 刷前按与正式镜像同一套断言校验**嵌入内核** md5，不要只校验整包。
- 出处：手册-上机执行手册.md:164-167。

### 5.2 软回退（不刷机，回到安全态）

顺序固定，不能颠倒（否则 governor 会被 hmbird 抢回去）：

1. `echo 0 > /proc/hmbird_sched/scx_enable`（关 hmbird）；
2. 逐个 policy `echo uag > /sys/devices/system/cpu/cpufreq/policyN/scaling_governor`；
3. 杀掉**两个**守护：`fengchi-watch.sh` 与 `fengchi-gov.sh`（只杀一个会被另一个拉起来）；
4. `ps` 复查残留进程与 `scaling_governor` 终态。
- 出处：手册-上机执行手册.md:164-167、成功-t194游戏态启用与退出完整还原.md:34-57。
