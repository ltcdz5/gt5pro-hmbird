设备：真我 GT5 Pro（RMX3888 / SM8650 / ColorOS 16）｜内核：自编 **opt60**（6.1.141 OKI）

## 一、结果

```

dmesg: [scx_gov][scx_gov_init] init cluster[0] done. ✓
       [scx_gov][scx_gov_start] start cluster[0] cluster_id[0] gov ✓
```

⇒ **自编内核提供 了 风驰所需的 `scx` 调速器，并且它真的启动、真的工作** ✓

## 二、正确用法（与本项目最初设想不同！）

风驰的开关**不在内核**，而在**厂商/云控那一侧**：

1. **内核**：提供 `scx`/hmbird 调速器（本项目的工作 ✓）+ 官方调度环境完整
2. **厂商栈**：`oplus_bsp_sched_ext.ko` 等（系统自带 ✓，按需加载）
3. **云控配置**：由 **COSA 云控**（或 SCRC 之类的注入模块）提供**每款游戏的适配配置**
4. **游戏助手**：受支持的游戏需在游戏助手列表中
5. 启动受支持游戏 ⇒ 系统**自动切到 `scx`** ⇒ 退出后自动切回

> ⛔ **绝对不要**用搞机工具/内核开关去**固定** scx 调度 —— 会**整机硬挂死**（本项目实测复现过；社区也明确警告）
> ⛔ **不要**使用 Scene 的调度 / 任何第三方调度、游戏线程模块
> ⛔ **不要**使用"官方调度屏蔽"类模块（如 IMS_VAROS）—— 与风驰直接冲突

## 四、如何判断风驰生效

启动受支持游戏后，看：
```
cat /sys/devices/system/cpu/cpufreq/policy*/scaling_governor
```
出现 `scx` ⇒ 生效 ✓（退出游戏后会切回 `walt`/`uag`，属正常）

## 五、本项目的边界（不变）

- 本项目把**接口层与 ABI 安全边界**做扎实了（导出集 15,489 逐名未变、493 个厂商模块不受影响）
- **内核开关**（`/proc/hmbird_sched/scx_enable`）那条路是 SM8750 血统、**出厂从未验证** ⇒ 手动强开会挂死 ✗
- 对外发布的镜像请保持 `CONFIG_HMBIRD_SCHED_CORE=n`（默认即 n）
