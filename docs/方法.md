# 方法

## 判据优先
一切以**设备实测**为准：
- **能否装载**：拿设备上的 **493 个厂商模块**逐个审计（缺失符号 / CRC 不符），这是最硬的判据；
- **能否启动**：刷机后第一件事是确认能正常启动；
- **不漂移**：导出集必须逐名不变（本项目基线 = **15,489** 名）。

## 基准 = 出厂内核
- 符号与 CRC：以出厂 `Image.stock` 的导出表（63,569 名）为参照；
- 结构体布局：以出厂 **BTF** 逐字段对偏移（`struct sched_ext_entity` 264 B / 23 成员、`task_struct` 195 字段 `scx`@3608 等）；
- 实现语义：关键函数与出厂**逐指令**对齐（例如 `task_is_scx()`）。

## 三道闸门
1. **全量模块审计**：493 个模块 missing=0 / crc=0；
2. **CRC 拒载**：会因 CRC 被拒载的模块数 = 0；
3. **新增导出遮蔽**：与厂商模块导出名交集 = 0。

## 已知机制（踩过的坑）
- **genksyms 只发结构体 tag**：实测结构体成员布局变化**不会**改变任何 CRC；CRC 差异来自 TU 上下文（`typedef` 展开等），因此个别符号只能定点覆写，并附 BTF/反汇编证据；
- **`hmbird_dir` 只导出未赋值**：会导致厂商模块的 proc 条目落到 `/proc` 根，而不是 `/proc/hmbird_sched`（"装载成功但无节点"的根因）；
- **条目两套必须互补**：内核侧建"前半套"、模块侧建"后半套"；重叠会让模块 `proc_create` 返回 NULL 而 init 失败；
- **开关会让导出集 +1**：`CONFIG_HMBIRD_SCHED=y` 曾使 `slim_dir` 多出一个导出 ⇒ 删除该导出后严格回到 15,489。
