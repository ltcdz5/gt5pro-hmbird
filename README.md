# gt5pro-hmbird

真我 GT5 Pro（RMX3888 / SM8650 / ColorOS 16 / 6.1.141 OKI 基线）上 **hmbird（风驰）**的移植记录与复现步骤。

> 本仓库内容由 **DeepSeek** 协助机主整理撰写。

## 这是什么

把 **风驰（scx/hmbird）**在我们的**自编内核**上跑到可用，并把"用户态需要配合的部分"收进**一个自编的小附加模块**，不依赖第三方调度/线程模块。

判据（怎么算可用）：游戏运行时执行
```
cat /sys/devices/system/cpu/cpufreq/policy*/scaling_governor
```
出现 `scx` ⇒ 生效；退出游戏后回到系统默认（本机为 `uag`）。

## 实现（三段式）

| 段 | 做什么 | 谁负责 |
|---|---|---|
| 一、内核 | 提供风驰调速器所需的接口与 ABI 兼容（导出集逐名不变、厂商模块不受影响）| 本项目自编内核 |
| 二、厂商栈 | 开机按依赖序加载 oplus_bsp_game_opt → oplus_bsp_sched_assist → oplus_bsp_sched_ext（最后者注册 scx 调速器）| fengchi-boot 附加模块 |
| 三、触发 | 检测厂商是否识别到游戏：有游戏 ⇒ scx；无游戏 ⇒ 系统默认 | fengchi-boot 的守护脚本 |

> 自编内核上，厂商"按需自动加载"的头部不会被触发，所以第二段需要这个小模块补齐；其余尽量交回出厂机制。

## 一键方案：fengchi-boot 附加模块

3 个文件、约 2 KB，装卸简单：
```
module.prop       模块描述
service.sh        开机：官调属性 + HAL 服务 → 按依赖序加载厂商栈 → MGLRU → 起守护
fengchi-gov.sh    守护：有游戏 ⇒ scx；无游戏 ⇒ 系统默认
```
它同时覆盖了两个常见小模块的功能：
- MGLRU 运行时恢复（原 lru_gen_on）
- horae 一次拉起（原 horae_once）

⇒ 这两个可以删掉。与风驰无关、可自行取舍：extreme_gt（只去锁帧/温控，不动调度）、quiet_logs（压日志刷屏）。

## 必须遵守

- 卸载"官方调度屏蔽"类模块（如 IMS_VAROS）：它会清空 persist.sys.orms.name / oiface.feature / hardcoder.name 并禁 OrmsUrcc / OiFace / GameOpt / COSA ⇒ 与风驰直接冲突
  - 用模块管理器正常卸载；改名目录会导致 KSU 卸载失败（它按目录名认模块）
- 关掉 Scene 的调度/调速器设置：Scene 的策略（如 walt）会盖掉系统默认
- 不要用任何工具"固定"风驰调度 —— 会整机硬挂死（内核里那条"手动开关"属于另一血统，本项目实测复现过）
- 对外发布镜像请保持内核侧的集成开关为默认关闭

## 方法

1. 以出厂内核为基准：符号、CRC、结构体布局逐条比对（结构体用 BTF 逐字段对偏移）；
2. 以设备上的厂商模块为硬判据：全量审计"能否装载"（缺失 / CRC 不符一律不放过）；
3. 每步过三道闸门 + 真机验收，过不了就回退。
